# کاردکس انبار (نسخه‌ی پایتون)

برنامه‌ی دسکتاپ (مک و ویندوز) برای کاردکس با **میانگین موزون متحرک**، **کنترل خودکار مغایرت‌ها** و **تخصیص خودکار کالا به فروش**.
جایگزین فایل اکسل «کاردکس آهن‌آلات» و پشتیبان **چند شرکت** با کدینگ کالای مستقل برای هر شرکت.

## نصب و اجرا (ساده‌ترین روش)
فایل زیپ را باز (Extract) کنید و **داخل همان پوشه** این کارها را بکنید.

**مک**
1. اگر Python ندارید، نسخه‌ی ۳٫۱۲ را از <https://www.python.org/downloads/macos/> نصب کنید (یک‌بار).
2. روی **`run_mac.command`** دوبار کلیک کنید ← Terminal باز می‌شود، بار اول چند دقیقه بسته‌ها را دانلود می‌کند و بعد برنامه باز می‌شود.
3. اگر مک اجازه نداد («unidentified developer»): راست‌کلیک روی فایل ← **Open** ← Open.
4. اگر فایل در ویرایشگر متن باز شد یا «permission denied» آمد: Terminal را باز کنید، بنویسید `chmod +x ` (با یک فاصله‌ی آخر)، فایل را داخل پنجره Terminal بکشید و Enter بزنید؛ سپس دوباره دوبار کلیک کنید. اگر باز هم مسدود بود: `xattr -dr com.apple.quarantine ` + کشیدن پوشه‌ی برنامه به Terminal.

**ویندوز**
1. اگر Python ندارید، نسخه‌ی ۳٫۱۲ را از <https://www.python.org/downloads/windows/> نصب کنید و در نصب‌کننده تیک **Add python.exe to PATH** را بزنید.
2. روی **`run_windows.bat`** دوبار کلیک کنید. بار اول چند دقیقه بسته‌ها را دانلود می‌کند.
3. اگر SmartScreen هشدار داد: More info ← Run anyway.

> فایل‌های `.sh` روی این پروژه استفاده نمی‌شوند؛ در مک فقط `.command` و در ویندوز فقط `.bat` را دوبار کلیک کنید.

## ساخت فایل اجرایی مستقل (اختیاری، بدون نیاز به Python برای کاربر نهایی)
PyInstaller برای هر سیستم‌عامل باید روی همان سیستم اجرا شود:
- **مک:** دوبار کلیک روی `build_mac.command` ← `dist/KardexApp.app`
- **ویندوز:** دوبار کلیک روی `build_windows.bat` ← `dist\KardexApp\KardexApp.exe`
- **هر دو بدون داشتن هر دو سیستم:** پروژه را در GitHub بگذارید و workflow پوشه‌ی `.github/workflows/build.yml` را اجرا کنید (Actions ← build ← Run workflow).

## اجرا از ترمینال (برای توسعه‌دهندگان)
```
pip install -r requirements.txt
python main.py
```

## شروع کار
1. **شرکت جدید** بسازید (هر شرکت کدینگ، تراکنش‌ها، تنظیمات و طرح فروش جدا دارد).
2. **ورود از اکسل** ← فایل شرکت را انتخاب کنید.
   - فایل اکسل قبلی (`..._v30.xlsm`) مستقیم وارد می‌شود؛ شیت‌های «کدینگ کالا»، «خرید» و «فروش» انتخاب می‌شوند و شیت‌های محاسباتی (ادغام، کاردکس زنده و …) نادیده گرفته می‌شوند.
   - اگر فایلی شیت کدینگ جدا نداشته باشد ولی شیت‌های تراکنش ستون «کد کالا» و «نام کالا» داشته باشند، کدینگ از روی همان‌ها ساخته می‌شود.
   - برای شرکت‌های دیگر: از منوی فایل «ساخت فایل نمونه‌ی ورود داده» را بزنید و همان قالب را پر کنید.
   - ستون‌های شناخته‌شده: کدینگ = `کد کالا، نام کالا`؛ تراکنش = `تاریخ، نوع (اول دوره/خرید/فروش)، طرف حساب، کد کالا، نام کالا، مقدار، فی`. تاریخ شمسی (۱۴۰۵/۷/۲۶ یا 1405-07-26)، میلادی و ارقام فارسی پذیرفته می‌شود.
3. تب **کنترل** را ببینید و ردیف‌های مغایر را با دوبار کلیک اصلاح کنید.
4. **خلاصه موجودی** موجودی، میانگین بها، ارزش و قیمت پیشنهادی فروش را نشان می‌دهد.
5. **تخصیص کالا:** تاریخ، خریدار و «مبلغ نهایی فاکتور (با مالیات)» را وارد (یا از اکسل paste) کنید ← «اجرای تخصیص» ← در صورت تأیید «ثبت به‌عنوان فروش».

## بازگردانی (Undo / Redo)
دکمه‌های «↶ بازگردانی» و «↷ ازنو» در نوار بالا و منوی «ویرایش» (میانبر Ctrl+Z و Ctrl+Y، در مک ⌘Z و ⇧⌘Z) آخرین عملیات را برمی‌گردانند. این موارد قابل بازگردانی‌اند: افزودن/ویرایش/حذف تراکنش و کالا، ورود از اکسل (یک مرحله)، حذف اطلاعات قبلی (یک مرحله)، ثبت فروش از تخصیص، ویرایش طرح تخصیص، تنظیمات، تغییر نام، ساخت و حذف شرکت. تا ۵۰ مرحله‌ی آخر نگه داشته می‌شود (در حافظه، فشرده)؛ با بستن برنامه پاک می‌شود، پس پشتیبان خودکار برای حذف‌های بزرگ همچنان وجود دارد. «بازیابی از پشتیبان» قابل بازگردانی نیست.

## فاکتور رسمی در تخصیص
در تب «تخصیص کالا» دو نوع ردیف دارید:
- **ردیف عادی:** فقط «مبلغ نهایی فاکتور (با مالیات)». برنامه کالا و تعداد را تعیین می‌کند.
- **فاکتور رسمی:** ستون‌های «کالا (کد یا نام)»، «مقدار» و «فی» را پر کنید؛ یا به‌جای فی، «مبلغ نهایی (با مالیات)» را بنویسید تا فی با نرخ مالیات همان کالا استخراج شود. این ردیف **دقیقاً همان مقدار و مبلغ** ثبت می‌شود (بدون گرد کردن و بدون قیمت‌گذاری مجدد)، و موجودی‌اش پیش از ردیف‌های عادی کنار گذاشته می‌شود. اگر در آن تاریخ موجودی کافی نباشد، با «رسمی — موجودی ناکافی» علامت می‌خورد؛ فاکتور رسمی حذف نمی‌شود و پس از ثبت در تب «کنترل» موجودی منفی نشان داده می‌شود.
- ستون‌ها (تاریخ، خریدار، کالا، مقدار، فی، مبلغ) را می‌توانید مستقیم از اکسل کپی و با «چسباندن» وارد کنید.

## نرخ ارزش افزوده‌ی هر کالا
هر کالا می‌تواند نرخ مالیات اختصاصی داشته باشد (مثلاً ۰٪، ۱۰٪ یا ۱۶٪). اگر ستون «نرخ ارزش افزوده» در شیت کدینگ فایل اکسل باشد (مثل فایل مجید یزدانی) خودکار خوانده می‌شود؛ در غیر این صورت نرخ پیش‌فرض شرکت (تب تنظیمات، ۱۰٪) اعمال می‌شود. در تب «کدینگ کالا» نرخ هر کالا قابل ویرایش است. نرخ در تخصیص (تعداد کالا بر اساس مبلغ نهایی با مالیات)، ستون‌های مالیات تب تراکنش‌ها و «قیمت پیشنهادی با مالیات» در خلاصه استفاده می‌شود. هزینه و میانگین بها بدون مالیات است، مثل اکسل.

## تنظیمات هر شرکت هنگام ورود از اکسل
درصد سود پیشنهادی (و در نسخه‌های جدید، آستانه‌های شیت «کنترل») از خود فایل خوانده می‌شود و برنامه می‌پرسد برای آن شرکت اعمال شود یا نه. خرید با فی صفر (کالای رایگان/جایزه) معتبر است و میانگین بها را پایین می‌آورد.

## دوره‌ی جدید و حذف اطلاعات قبلی
- **«حذف اطلاعات قبلی…»** (نوار بالا یا منوی فایل): تراکنش‌ها را کلاً یا «تا یک تاریخ» حذف می‌کند؛ طرح تخصیص و (در صورت حذف کامل) کدینگ را هم می‌شود پاک کرد.
- **انتقال موجودی پایان دوره:** با روشن کردن این گزینه، موجودی و میانگین بهای هر کالا تا تاریخ پایان دوره به‌صورت یک ردیف «اول دوره» ثبت می‌شود و موجودی/میانگین تغییر نمی‌کند. اگر فایل دوره‌ی جدید خودش «اول دوره» دارد، این گزینه را روشن نکنید.
- **ورود از اکسل ← «جایگزینی»:** تراکنش‌های قبلی (و در صورت انتخاب، کدینگ) حذف و داده‌ی فایل جدید وارد می‌شود.
- قبل از هر حذف/جایگزینی، پشتیبان خودکار در `~/KardexApp/backups` ساخته می‌شود (۳۰ نسخه‌ی آخر). با منوی فایل ← «بازیابی از پشتیبان…» برمی‌گردد.

## تفاوت‌ها با فایل اکسل
- **لینک خارجی و وابستگی به نام فایل ندارد.** آستانه‌ها در «تنظیمات» هر شرکت ذخیره می‌شود.
- ظرفیت ۱۰۰۰ ردیف و کندی COUNTIFS ندارد.
- تاریخ‌ها اعتبارسنجی و یکدست می‌شوند (فاصله‌ی اضافی، ارقام فارسی، تاریخ‌های ناممکن مثل ۳۰ اسفند سال غیرکبیسه).
- کالا با **کد** ذخیره می‌شود، نه نام؛ «ي/ی» و «ك/ک» و فاصله‌ها در تطبیق نام هنگام ورود از اکسل یکسان می‌شوند.
- نرخ مالیات، درصد سود، گرد کردن و نحوه‌ی گرد کردن مقدار پارامتر هستند، نه عدد ثابت.
- تخصیص: موجودی بین ردیف‌ها کم می‌شود (در ماکرو ردیف‌های قبلاً تخصیص‌یافته کم نمی‌شدند)، و با گزینه‌ی «تقسیم بین چند کالا» باقیمانده‌ی تخصیص جزئی از کالای بعدی تأمین می‌شود. با خاموش کردن این گزینه رفتار دقیقاً مثل ماکرو است.

## منطق محاسبه (مطابق اکسل)
- ترتیب تراکنش‌های هر کالا: تاریخ ← ورودی (اول دوره/خرید) قبل از خروجی ← ترتیب ثبت.
- خرید: `میانگین = (موجودی قبل × میانگین قبل + مقدار × فی) / موجودی جدید`؛ فروش میانگین را تغییر نمی‌دهد.
- قیمت پیشنهادی = `MROUND(میانگین × (1 + درصد سود), مضرب گرد کردن)`.
- مغایرت‌ها: تاریخ نامعتبر، کالای نامعتبر، شروع موجودی منفی، انحراف نرخ خرید از میانگین قبل بیش از آستانه، فروش با سود کمتر از حداقل.
- تخصیص (حالت پیش‌فرض) با **موجودی و میانگین بهای همان تاریخ فروش** انجام می‌شود: خریدهای بعد از تاریخ فروش اثری ندارند، میانگین با هر خرید تغییر می‌کند، و فروش‌های ثبت‌شده‌ی بعدی منفی نمی‌شوند. اگر در «تنظیمات» این گزینه را خاموش کنید، مثل ماکرو از موجودی/میانگین نهایی استفاده می‌شود.
